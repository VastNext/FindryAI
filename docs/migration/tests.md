# 验收规范 v1

本文件定义待实现的套件 S01–S09，替代总方案 T01–T19 的概括描述。先读 contracts.md。所有用例当前 NOT_RUN；本次文档交付不声称它们已通过。

## 测试输入与结果

`bin/verify` 只从 inventory 读取目标。inventory 缺环境 ID、变量身份、测试账号/夹具、批准或正式验收所需阈值则退出 20。S09 基线测量是唯一允许性能阈值未定的模式，按下面安全停止规则执行，结果只为 MEASURED、不能判容量 PASS。执行前核对主机及数据集属于批准环境；staging 被配置成生产目标必须拒绝。负载/故障/写测试禁止 production 和 production-candidate。

每个子用例结果记录 case_id、status、assertions、started_at、finished_at、source_commit、image_digest、config_hash、fixture_version、evidence_paths。总结果：任何 FAIL 则 FAIL；无 FAIL 但有必测 BLOCKED/NOT_RUN 则 BLOCKED；全部必测 PASS 才 PASS。N/A 要有协调者批准引用。

固定夹具：两个已发布 item、一条草稿、一个已下架 item、一个 category、一个普通用户和管理员、一个测试 Checkout Session、两个测试收件人。只使用专用测试数据集中的确定 ID，fixture 初始化/清理输出 ID 清单；清理只能删除本轮创建的 ID。fixture 为空必须 BLOCKED，不能以空列表的 200 判成功。

单个 HTTP 只读请求超时 30 秒，不隐式重试；流式请求最多 120 秒；发布故障实验总超时 10 分钟；恢复和负载超时由已批准 inventory 指定。超时归 FAIL/NEEDS_RECONCILE，不能自动反复执行可能有副作用的操作。

## S01：镜像与秘密边界（D01）

1. 干净 checkout 无本地 env 构建，使用清单中指定构建变量/临时秘密；必须生成 linux/amd64 镜像，记录 digest 与 commit。
2. 以必需运行秘密启动，健康监听成功；缺 SANITY_API_TOKEN、空必填值分别预检返回 20，不能声称“只含公开变量即可运行”。
3. 用可识别的假秘密标记扫描镜像解包层、历史与日志，不出现该标记；真实秘密只做安全扫描结果摘要，不回显命中内容。
4. 非 root 运行且必要缓存可写；应用不能读取其他站点秘密或 Docker socket。文件内容和容器配置均检查。

## S02：路由、内容与缓存（D01）

1. 首页、已发布 item/category、搜索页面和真实静态资源返回 200，断言标题/夹具文本、资源类型及 JS/CSS 非空；不存在 item 返回 404。
2. 草稿与下架条目不可被匿名读取为已发布正文；robots/sitemap 使用实际路由输出，链接域名符合当前环境，不混入候选正式公开链接。
3. 同一条目冷访问后连续 3 次访问，结合实际缓存头与渲染/依赖请求计数确认命中，不能仅凭速度判断；可观测性缺失则先补测试观测，不默认命中。
4. staging 编辑条目并触发失效，重复请求最多等待 30 秒，新正文出现；下架后不可读。记录每一步版本和内容摘要。

## S03：平台隔离与 TLS（D02）

1. 两个演示站点分别返回唯一标识，重启其中一个不重启另一个；各自后端网络和秘密隔离。
2. 从隔离主机外探测实际端口：只允许批准入口和管理 SSH；3000、2019、数据库端口不可达。不能只检查 UFW。
3. HTTP 到 HTTPS 为预期重定向，证书 SAN 匹配；伪造未知 Host 不进入目标站。管理 API 不对外可达。
4. 候选入口未授权请求被拒，noindex 不替代访问控制；第三方回调例外仅限指定路径且独立验签。
5. 主机重启后服务及证书状态恢复；同一初始化重复执行不删除任何既有站点资源。仅隔离主机演练重启。

## S04：状态机与并发（D03/D06）

1. 不存在镜像、候选健康失败、磁盘/内存不足、错误 Caddy 配置：旧站持续响应，新版不接流，工具非零退出。
2. 同站点两个 promote 并发：最多一个成功，另一等待后按 generation 冲突拒绝；不同站点并发后两个映射均正确。
3. A 切流后 B 合法更新，A 的延迟 rollback 必须返回 30，不撤销 B。
4. 在重载前、重载后状态落盘前分别中断进程：status/reconcile 能识别真实状态，不重复切流或删除活动版本；不能确认则返回 40。
5. 秘密路径、站点名、镜像仓库、shell 元字符、任意 Compose 文件输入均做负向测试；审批缺失/过期/版本错配返回 20 或 30，不调用写适配器。
6. cleanup 只删除本操作的非活动候选；模拟锁超时不能删锁文件绕过。unit 适配器与真实双站点 Caddy 均必须通过。

## S05：业务副作用（D05）

执行前 D05a 已审查。支付测试全部为测试模式及专用数据集。

1. 同一 session 顺序重放 3 次、并发 2 次：订单/付费状态一致且仅一次业务履约；metadata 缺失、签名错误、条目不存在均不产生半成品。
2. 在履约事务前/中模拟失败，恢复重试后条目与订单一致；不能出现订单存在而付费状态未更新却返回完成。
3. 通知确定失败、已发送、发送结果未知三种状态分别测试。未知状态不自动重发，记录人工核对；不把外部 exactly-once 当既有保证。
4. 周报夹具必须有条目及两个收件人；一个成功、一个失败后重试，成功者不重复发送。dryRun=1 不实际发信。发送未知结果同样进入核对。
5. 两条 cron 错误/缺失 Bearer 返回 401；候选/恢复默认不运行定时任务；同窗口并发遵循已批准唯一所有权。
6. 最低安全回滚版本对同一夹具重放满足上述约束。历史订单兼容测试必须存在，不能只验证新数据。

## S06：真实蓝绿集成（D06）

1. 候选预热后编辑/下架，再 promote；新版不展示旧正文。接流后编辑，再 rollback；旧版也不得复活旧正文。失败时阻止对应回滚目标。
2. 浏览器在旧版打开页面、保留表单与延迟资源请求，切新版后提交/导航；记录旧静态资源、RSC、Server Actions 行为。必须完成安全操作或明确提示刷新，不能静默丢失已提交数据。策略不满足则退回协调者设计，禁止自行假定兼容。
3. 模拟流式响应至少 3 块、间隔 1 秒，首块在末块前到达；重载期间旧连接遵循已批准排空策略。真实翻译只做一次获批有限文本调用，不进入压力循环。
4. staging OAuth 登录退出、匿名 dashboard 拦截、Studio 读写权限正确；回调留在 staging。生产 candidate 仅做读探针，不复用 staging 写测试。

## S07：备份、告警与恢复（D04）

1. 已知文件夹具备份到批准异机存储，恢复到空隔离目标，逐文件哈希匹配；证书/配置/密钥引用完整，秘密不进入日志。
2. 模拟上传失败、损坏对象、过期快照；不得更新成功恢复点。用注入时钟而非修改主机时间验证超过 18 小时预警、24 小时违约。
3. 上传延迟情况下，以快照覆盖的数据时刻计龄，不按完成上传时间刷新。
4. 使用异机保管凭据在独立获批 Linux 环境恢复；记录 RTO。仅同一 VPS 的目录恢复不能宣称整机灾备通过。恢复后 cron/真实发信默认关闭。

## S08：首次 CI 交接（D06）

1. 候选构建入口只构建/推送；不调用任何 Vercel/VPS 生产变更，验证 workflow 权限及调用记录。
2. 在演示仓库模拟 tag、手动触发、旧运行 rerun；启用唯一目标后只有 VPS 流程可获生产部署权限，旧 workflow 无可用生产写凭证。
3. 生产保护未批准时流水线停在审批前；获批 digest/config 与实际部署一致。
4. 真实仓库的冻结在 D08 执行，不因演示 PASS 就假定旧 runs 已清空。

## S09：容量与独立接手（D07）

协调者提交 profile：预热 20 个条目及首页、固定 5/10/20 并发各 5 分钟、双版本加演示站同时运行；另以 2 并发访问 20 个冷条目。AI 付费接口不参与负载。默认建议仅为实验输入，执行前用户批准；不得在生产压测。

inventory 的 capacity_mode 分为 baseline 和 acceptance。baseline 必须具备负载和安全授权，允许 p95/CPU 性能放行阈值尚未定；发生 OOM、非预期重启、5xx 或 MemAvailable 低于 20% 立即停止。只输出测量报告（measurement_status=MEASURED，套件 status=BLOCKED，退出 20），交用户批准具体性能阈值。acceptance 必须填写全部阈值，重跑同一 profile 后才能给出 PASS。测量成功不是验收成功，安全停止为 FAIL。

必须记录每档吞吐、p95、5xx、CPU、RSS、MemAvailable、OOM、磁盘及缓存计数。无 OOM/意外重启、无非预期 5xx、可用内存保持至少 20% 为建议硬门禁；p95/CPU 等具体上限由测量建议经用户批准写入 inventory，未定值 BLOCKED。不能在失败后自行降低并发放宽上限。

未参与开发的代理从空隔离环境按 D07 操作附录完成 prepare/promote、故障切换、rollback、恢复。不询问架构问题且所有断言通过才可 PASS；若需临场设计，记录具体缺失步骤并退回所属任务。

## 证据失效规则

源代码或镜像变更重跑 S01/S02 及受影响功能；发布/入口变更重跑 S03/S04/S06/S08；支付/Schema/cron 变更重跑 S05/S06；备份变更重跑 S07；资源配置变更重跑 S09。任何变更重跑执行器自检与环境预检。生产 digest 与批准证据不一致时直接 BLOCKED，由协调者批准重测范围，不自动继承旧 PASS。
