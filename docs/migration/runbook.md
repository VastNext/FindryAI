# 生产操作单：受门禁保护的模板

状态：**不可执行，等待 D07 实际工具和已验证命令附录。** 此文件说明每步谁做、输入、放行及停止条件；不伪造还不存在的安装和恢复命令。实际执行必须同时持有 `docs/operations-validated.md`、精确版本与私有 inventory。

## 生产授权单

每次授权注明操作 ID、执行者、主机、站点、资源 ID、提交、digest、配置哈希、expected_generation、UTC 有效窗口、允许步骤和失败恢复范围。P0–P4 的准备批准不包括 P5 DNS 切流。生产只有一名写执行者；其他 AI 只读查看脱敏监控。

## P0：确认工具可执行

输入 D07 PASS 和独立接手演练报告。核对实际 CLI `--help`、版本、文件哈希与操作附录一致。附录每步必须含工作目录、已执行过的命令、输入文件、预期退出码/JSON、超时和恢复动作。任何命令未验证则停止，不在生产临时补脚本。

通过：S01–S09 的适用证据齐全；不适用有批准，必测缺失不能豁免为 PASS。没有生产配置改变。

## P1：保存现状与批准准备窗口

只读记录 DNS 每条 ID、类型、内容、TTL、代理状态；Cloudflare SSL/规则；旧 Vercel 部署/调度；GitHub workflows 与在途/排队 runs；实际 OAuth、Stripe、Sanity 回调和生产变量名。秘密安全注入，不进入记录。

获取控制台救援验证、系统更新重启授权与有效 SSH 指纹。确认备份存储、异机密钥保管及单机停站风险已由用户接受。否则 BLOCKED。旧 Vercel 402 仅作为事实，不作为“已禁用调度”的证据。

## P2：主机与入口准备

按 D02 已验初始化操作附录，在维护独占锁内安装 Compose/更新系统、配置日志、防火墙和 Caddy。先验证新 SSH 会话再关闭旧会话；每次重启后重新核对主机身份和服务。不得批量删除已有目录/容器。

正式域名证书必须在改变业务流量前就绪。由 D00 选定并验证预签发方式（如 DNS-01 的最小权限模块或已批准证书导入）；未确定时停止，不先改业务 DNS 来碰运气。先在受控环境验证 Cloudflare 同等代理配置，正式完整链路仍须 P5 后实测，不能在切流前虚报已通过。

通过：端口/TLS/重启证据匹配，站点实例隔离，外部探测通过，状态文件完整。失败按已批准救援步骤恢复，不修改其他业务。

## P3：生产候选与恢复准备

用独立候选构建入口生成正式公开配置镜像，固定 digest；通过 preflight 后 prepare，不 promote。候选受保护、调度关闭，只做生产只读探针；写测试已在 staging 完成。

完成真实异机备份和恢复检查，登记最低安全回退版本。首次没有历史稳定版本时，把“重建当前已验镜像”明确记为应用恢复路径，不称为历史回滚；主机坏掉需独立恢复目标或明确停服风险接受。外部生产写入验收不能由 staging PASS 替代，制定最小操作、账号、预期记录数及人工核对人，另获批准。

通过：候选正文/资源/依赖只读检查通过，备份年龄符合目标，恢复证据可追溯。失败不改正式入口。

## P4：旧任务与流水线交接

1. 冻结旧生产 tag/手工入口；保存配置，确认在途与排队运行结束或取消。冻结旧 Preview 中可修改 production 变量的路径。
2. 撤销旧部署 workflow 可用的生产写凭证或权限，验证历史 rerun 不能再发布；保留必要的只读排障访问。不要删除其他项目共用凭证，若共用先隔离。
3. 禁用旧平台 cron 并取得控制面证据，确认在途任务结束；没有证据则新调度保持关闭，记录漏发风险，不能开启两套。
4. 合入批准的新 workflow 和项目规约，生产环境审批仍锁定；验证构建入口不依赖 `v*`，准备下一 tag 明确目标，仅由授权用户或执行者触发。

通过：唯一发布目标和唯一调度所有权明确。冻结造成可用性/漏发影响必须属于本次批准范围；不能悄悄提前执行。

## P5：单独批准后切流

向用户交付候选证据、精确 DNS 旧/新值、目标 digest、恢复边界与时窗，取得切流授权。重新 preflight 和核对 generation/配置/备份；证据过期停止。

先把 Caddy 正式 Host 指向已验候选且验证源站 TLS，再按批准记录 ID 逐条更新 DNS A/AAAA/CNAME/代理设置。旧值与审批快照不一致时 CONFLICT；部分成功时保存实际状态并按授权补偿处理。保持 Full (strict) 等已经验收的 SSL 配置，不切 Flexible。

切流后从两条独立网络验证正式域名完整链路、TLS、主页、深层链接、静态资源、只读 API；记录新旧 DNS 传播。不得以仅 curl 源 IP 成功替代域名验证。故障按已登记 VPS 版本/入口恢复路径处理，不盲目切回 402 Vercel。

## P6：业务验收与观察

经授权执行最小生产写验收；Stripe 不用真实收费代替测试模式机制验证，无法安全执行的生产场景须用户明确接受风险或保持相关功能关闭。登记外部事件与 Sanity 状态，不以 HTTP 200 替代完整履约。

只有旧 cron 排空和所有权转移证据齐全才启用新调度。周报下一自然窗口尚未到时标为 NOT_RUN；不得为验收向全量用户强制补发。持续观察 24–48 小时错误率、资源、备份、回调和真实任务结果。按授权完成首次正式 tag 发布；独立回滚演练可在 staging，生产回滚需要明确批准。

## P7：交接与旧资源退役

输出当前 digest、配置版本、秘密保管引用、监控与备份负责人、恢复报告、已通过与待验证项。旧配置/镜像按获批保留期留存，真实删除另获批准；保留期限未定时不自行清除。

下一站点只复用平台契约；KrillionClues 技术栈/数据库未知，禁止据本操作单直接迁它的数据。

## 任意阶段强制停止

退出码非零、审批过期、环境身份不符、旧值变更、秘密泄漏、未知外部副作用、没有恢复目标、发现另一生产写执行者：停止后续写操作，保存脱敏证据、调用只读 status，并报告协调者。仅允许授权单中明确的救援动作；没有授权时不得自动回滚或重试支付/邮件。
